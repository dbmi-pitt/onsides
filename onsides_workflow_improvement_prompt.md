# Proposal for Improving OnSides Data Loading Workflow

**Context:** During the migration of `cem_development_2025`, we discovered that while tables were restored, their associated auto-increment sequences (specifically for `product_label` and `vocab_meddra_adverse_effect`) were missing or not linked. This often happens/persists if the original DDL used implicit `SERIAL` types but the dump/restore process didn't capture the dependency perfectly, or if `CREATE TABLE` scripts are separated from sequence handling.

**Recommended Prompt for Refactoring:**

Use the following prompt to ask an AI agent or developer to robustify the ETL scripts:

> "I need to refactor the database DDL and loading scripts for the `onsides` project in PostgreSQL. We recently faced an issue where `pg_dump`/`restore` lost the auto-increment sequences for key tables like `product_label`.
>
> Please update the table definitions and loading process with these requirements:
>
> 1.  **Modern Identity Columns:** Replace legacy `SERIAL` types with `GENERATED BY DEFAULT AS IDENTITY`. This binds the sequence lifecycle tightly to the column and handles permissions more cleanly.
> 2.  **Post-Load Synchronization:** Create a standard 'post-load' SQL script that iterates through all identity columns in the schema and runs mentions `setval(..., max(id))` to ensure sequences are never out of sync with imported data.
> 3.  **Explicit Ownership:** Ensure all created objects (tables, sequences, views) are explicitly owned by the group role `cem_dev_25_rw_grp` immediately upon creation, rather than the individual running the script."

---

**Immediate Benefit:**
- Prevents "duplicate key value violates unique constraint" errors immediately after a fresh data load.
- Simplifies permission management (no separate `GRANT` needed for the sequence if it's an Identity column).
